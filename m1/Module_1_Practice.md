# easy

## 1. Задание 1. Найдите ошибку в рассуждении

### Персонаж А

**Ошибка:** путает генерацию с поиском. LLM не «находит» информацию, а предсказывает вероятный текст; запрос без контекста даёт усреднённый результат.

**Правильное понимание:** промпт — это постановка задачи. Чем точнее заданы роль, аудитория, формат и ограничения, тем полезнее ответ. Промпт-инжиниринг — необходимый навык, а не формальность.

### Персонаж Б

**Ошибка:** принимает убедительность за достоверность. Это риск галлюцинаций — выдуманных цифр, тикеров и дат. Финансы — зона обязательной проверки.

**Правильное понимание:** уверенный тон не гарантирует правды. Факты и цифры проверяются по независимым источникам; в решениях с высокой ценой ошибки ИИ — черновик, а финальное решение принимает человек.

### Персонаж В

**Ошибка:** преждевременная автоматизация. Сразу предлагает API и «всё автоматизировать», хотя к API переходят после того, как процесс освоен вручную через веб-интерфейс.

**Правильное понимание:** сначала нужен пилот на веб-интерфейсе — проверить ценность и отладить промпты. API подключают, когда задача регулярно повторяется и ручной процесс уже отлажен.

## Задание 1. Оптимизируйте бюджет или время

| Задача | Способ работы | Обоснование |
|---|---|---|
| Создание контента для соцсетей | Веб-интерфейс: GigaChat / YandexGPT | 30 постов в месяц; нужен контроль стиля и креатива, поэтому человек редактирует каждый пост. |
| Ответы на вопросы клиентов в чате | API: GigaChat / YandexGPT API + бот | 20–30 однотипных вопросов в день; ручной ввод съедает время, а API автоматизирует поток. |
| Генерация идей для новых товаров | Не автоматизируем; веб-интерфейс, раз в месяц | Разовая задача, а ошибка в выборе товара дороже экономии времени. |

### Посты

Раз в месяц ИИ генерирует контент-план на 30 тем и по 3–5 вариантов текста на каждую тему. Владелец выбирает вариант, редактирует его, добавляет фото и цены, затем публикует. Раз в месяц проводится анализ охватов и корректировка тем.

### Чат

Клиент пишет в чат, ИИ определяет тему — наличие, доставка, оплата — и отвечает по актуальной базе знаний магазина. Сложные вопросы и жалобы передаются человеку. Цены и наличие ИИ не выдумывает, а берёт из каталога.

## Задание 3. Оцените риски стратегии

### Анализ разговоров

**Риск 1 — конфиденциальность.** Аудиозаписи содержат персональные данные клиентов и сотрудников. Нельзя отправлять такую информацию в открытые модели.

**Контроль:** использовать локальные или корпоративные модели с шифрованием; анонимизировать записи перед обработкой.

**Риск 2 — галлюцинации и неправильная интерпретация.** Нейросеть может неверно понять контекст разговора и, звуча уверенно, дать ошибочные рекомендации по качеству обслуживания.

**Контроль:** все выводы ИИ должны проверяться менеджером перед использованием; нельзя полностью доверять оценке ИИ.

### Составление графика

**Риск 1 — конфиденциальность.** Персональные данные о предпочтениях сотрудников — выходные, медицинские ограничения — относятся к конфиденциальным.

**Контроль:** использовать локальное решение; ограничить доступ к данным; не передавать их в открытые сервисы.

**Риск 2 — галлюцинации и логические ошибки.** Нейросеть может создать нереальный график: нарушить трудовое законодательство или создать пересечения смен, не зная точных правил.

**Контроль:** вручную проверить каждый график перед внедрением; добавить валидацию по трудовому законодательству.

### Выбор инициативы

**Выбор: Инициатива Б.**

Оба варианта содержат риски, но Инициатива Б менее опасна: её результаты проще проверить, поскольку логика графика явная, а данные более структурированы. Инициатива А связана с оценкой людей на основе ИИ, что, согласно материалу курса, несёт этический риск и требует безусловной проверки человеком. При этом оба решения должны использовать только локальные модели из-за конфиденциальности данных.

## Задание 1. Разработайте стратегию внедрения ИИ в личную или учебную деятельность

Стратегический документ: внедрение ИИ в учебную деятельность тестировщика
Самоанализ
Сфера для улучшения: учебная деятельность в рамках курса «ИИ для тестировщиков» и подготовка к практическому применению ИИ в ручном и автоматизированном тестировании.

Текущая ситуация:

Прохожу курс по применению ИИ в тестировании.

Планирую уделять учёбе не менее 2 часов в день, 5 дней в неделю.

Хочу углубляться в материалы курса и применять знания на практике.

Работаю с корпоративной LMS, занимаюсь ручным тестированием и начинаю осваивать автоматизацию.

Использую Playwright, Python, PyCharm, VS Code и Postman.

Доступны Claude, локальные модели и корпоративный ИИ.

Реальные пользовательские данные использовать нельзя: только тестовый стенд, моки и синтетические данные.

Исследование возможностей
Playwright Codegen и ИИ
Playwright позволяет записывать действия пользователя в браузере и генерировать исходный код теста с помощью Codegen.

Инструменты: Playwright Codegen, VS Code/PyCharm, Claude или корпоративный ИИ.

Подход: записать базовый сценарий, затем передать код ИИ для рефакторинга в Page Object Model и добавления assertions.

Сильные стороны: быстрый старт, селекторы основаны на реальном DOM.

Слабые стороны: сгенерированный код может быть хрупким и требовать ручной доработки.

Claude API для тест-данных
Claude поддерживает prompt caching: повторяемые части промпта можно кэшировать, снижая задержку и стоимость последующих запросов.

Инструменты: Claude API, Python, OpenAPI, JSON Schema.

Подход: ИИ получает обезличенные тест-кейсы и схемы API, генерирует fixtures и mock-ответы.

Сильные стороны: масштабируемость, единый стиль данных, возможность интеграции в CI.

Слабые стороны: возможны неверные поля API и логики; нужна валидация и ручное ревью.

ИИ для регрессионного анализа
ИИ помогает сопоставить изменение кода или API с картой зависимостей сервисов и выбрать релевантный набор тестов.

Инструменты: корпоративный ИИ, Python, pytest markers, Playwright.

Подход: для каждого сервиса хранится манифест зависимостей, критичных сценариев и тест-файлов.

Сильные стороны: быстрее обратная связь, меньше лишних прогонов.

Слабые стороны: при неполной карте зависимостей возможны пропуски критичных проверок.
