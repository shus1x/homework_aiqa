# Easy

## Задание 1. Найдите ошибку в рассуждении

### Персонаж А

**Ошибка:** путает генерацию с поиском. LLM не «находит» информацию, а предсказывает вероятный текст; запрос без контекста даёт усреднённый результат.

**Правильное понимание:** промпт — это постановка задачи. Чем точнее заданы роль, аудитория, формат и ограничения, тем полезнее ответ. Промпт-инжиниринг — необходимый навык, а не формальность.

### Персонаж Б

**Ошибка:** принимает убедительность за достоверность. Это риск галлюцинаций — выдуманных цифр, тикеров и дат. Финансы — зона обязательной проверки.

**Правильное понимание:** уверенный тон не гарантирует правды. Факты и цифры проверяются по независимым источникам; в решениях с высокой ценой ошибки ИИ — черновик, а финальное решение принимает человек.

### Персонаж В

**Ошибка:** преждевременная автоматизация. Сразу предлагает API и «всё автоматизировать», хотя к API переходят после того, как процесс освоен вручную через веб-интерфейс.

**Правильное понимание:** сначала нужен пилот на веб-интерфейсе — проверить ценность и отладить промпты. API подключают, когда задача регулярно повторяется и ручной процесс уже отлажен.

## Задание 1. Оптимизируйте бюджет или время

| Задача | Способ работы | Обоснование |
|---|---|---|
| Создание контента для соцсетей | Веб-интерфейс: GigaChat / YandexGPT | 30 постов в месяц; нужен контроль стиля и креатива, поэтому человек редактирует каждый пост. |
| Ответы на вопросы клиентов в чате | API: GigaChat / YandexGPT API + бот | 20–30 однотипных вопросов в день; ручной ввод съедает время, а API автоматизирует поток. |
| Генерация идей для новых товаров | Не автоматизируем; веб-интерфейс, раз в месяц | Разовая задача, а ошибка в выборе товара дороже экономии времени. |

### Посты

Раз в месяц ИИ генерирует контент-план на 30 тем и по 3–5 вариантов текста на каждую тему. Владелец выбирает вариант, редактирует его, добавляет фото и цены, затем публикует. Раз в месяц проводится анализ охватов и корректировка тем.

### Чат

Клиент пишет в чат, ИИ определяет тему — наличие, доставка, оплата — и отвечает по актуальной базе знаний магазина. Сложные вопросы и жалобы передаются человеку. Цены и наличие ИИ не выдумывает, а берёт из каталога.

## Задание 3. Оцените риски стратегии

### Анализ разговоров

**Риск 1 — конфиденциальность.** Аудиозаписи содержат персональные данные клиентов и сотрудников. Нельзя отправлять такую информацию в открытые модели.

**Контроль:** использовать локальные или корпоративные модели с шифрованием; анонимизировать записи перед обработкой.

**Риск 2 — галлюцинации и неправильная интерпретация.** Нейросеть может неверно понять контекст разговора и, звуча уверенно, дать ошибочные рекомендации по качеству обслуживания.

**Контроль:** все выводы ИИ должны проверяться менеджером перед использованием; нельзя полностью доверять оценке ИИ.

### Составление графика

**Риск 1 — конфиденциальность.** Персональные данные о предпочтениях сотрудников — выходные, медицинские ограничения — относятся к конфиденциальным.

**Контроль:** использовать локальное решение; ограничить доступ к данным; не передавать их в открытые сервисы.

**Риск 2 — галлюцинации и логические ошибки.** Нейросеть может создать нереальный график: нарушить трудовое законодательство или создать пересечения смен, не зная точных правил.

**Контроль:** вручную проверить каждый график перед внедрением; добавить валидацию по трудовому законодательству.

### Выбор инициативы

**Выбор: Инициатива Б.**

Оба варианта содержат риски, но Инициатива Б менее опасна: её результаты проще проверить, поскольку логика графика явная, а данные более структурированы. Инициатива А связана с оценкой людей на основе ИИ, что, согласно материалу курса, несёт этический риск и требует безусловной проверки человеком. При этом оба решения должны использовать только локальные модели из-за конфиденциальности данных.

# Hard

## Задание 1. Разработайте стратегию внедрения ИИ в личную или учебную деятельность

### Стратегический документ: внедрение ИИ в учебную деятельность тестировщика

#### Самоанализ

**Сфера для улучшения:** учебная деятельность в рамках курса «ИИ для тестировщиков» и подготовка к практическому применению ИИ в ручном и автоматизированном тестировании.

**Текущая ситуация:**

- Прохожу курс по применению ИИ в тестировании.
- Планирую уделять учёбе не менее 2 часов в день, 5 дней в неделю.
- Хочу углубляться в материалы курса и применять знания на практике.
- Работаю с корпоративной LMS, занимаюсь ручным тестированием и начинаю осваивать автоматизацию.
- Использую Playwright, Python, PyCharm, VS Code и Postman.
- Доступны Claude, локальные модели и корпоративный ИИ.
- Реальные пользовательские данные использовать нельзя: только тестовый стенд, моки и синтетические данные.

#### Задачи для делегирования ИИ

| Задача | Текущее время | Как поможет ИИ |
|---|---:|---|
| Формулирование вопросов к требованиям | 30–60 мин | Выявит неясности, граничные случаи и противоречия в требованиях |
| Создание чек-листов и тест-кейсов | 1–2 ч | Сгенерирует черновик по user story, требованиям и MD-документации |
| Подготовка тестовых данных | 30–90 мин | Создаст синтетические данные, fixtures и mock-ответы API |
| Написание черновиков Playwright-тестов | 2–4 ч | Подготовит черновик Python/Playwright-теста, Page Object и assertions |
| Разбор логов и ошибок | 30–60 мин | Выделит ключевые ошибки, возможные причины и вопросы для проверки |
| Составление regression impact map | 1–2 ч | Определит затронутые сервисы, роли и сценарии после изменения |
| Ревью результатов ИИ | 30–60 мин | Поможет проверить тест-кейсы, данные, код и выводы на полноту и ошибки |

#### Исследование возможностей

##### Playwright Codegen и ИИ

Playwright позволяет записывать действия пользователя в браузере и генерировать исходный код теста с помощью Codegen. [31][32]

- **Инструменты:** Playwright Codegen, VS Code/PyCharm, Claude или корпоративный ИИ.
- **Подход:** записать базовый сценарий, затем передать код ИИ для рефакторинга в Page Object Model и добавления assertions.
- **Сильные стороны:** быстрый старт, селекторы основаны на реальном DOM.
- **Слабые стороны:** сгенерированный код может быть хрупким и требовать ручной доработки.

##### Claude API для тест-данных

Claude поддерживает prompt caching: повторяемые части промпта можно кэшировать, снижая задержку и стоимость последующих запросов. [33][40]

- **Инструменты:** Claude API, Python, OpenAPI, JSON Schema.
- **Подход:** ИИ получает обезличенные тест-кейсы и схемы API, генерирует fixtures и mock-ответы.
- **Сильные стороны:** масштабируемость, единый стиль данных, возможность интеграции в CI.
- **Слабые стороны:** возможны неверные поля API и логики; нужна валидация и ручное ревью.

##### ИИ для регрессионного анализа

ИИ помогает сопоставить изменение кода или API с картой зависимостей сервисов и выбрать релевантный набор тестов.

- **Инструменты:** корпоративный ИИ, Python, pytest markers, Playwright.
- **Подход:** для каждого сервиса хранится манифест зависимостей, критичных сценариев и тест-файлов.
- **Сильные стороны:** быстрее обратная связь, меньше лишних прогонов.
- **Слабые стороны:** при неполной карте зависимостей возможны пропуски критичных проверок.

#### Выбор инструментов

| Задача | Инструмент | Формат | Обоснование |
|---|---|---|---|
| Вопросы к требованиям | Claude или корпоративный ИИ | Веб-интерфейс | Удобно для итеративного анализа текста |
| Чек-листы и тест-кейсы | Claude или корпоративный ИИ | Веб-интерфейс | Быстрая генерация и правка черновиков |
| Тест-данные и моки | Claude API или корпоративный ИИ | API | Нужны повторяемость, шаблоны и валидация |
| Черновики автотестов | Playwright Codegen + Claude | IDE и веб-интерфейс | Codegen фиксирует реальные действия, ИИ улучшает структуру |
| Разбор логов | Корпоративный ИИ / Claude API | API | Нужна обработка логов, скриншотов и трейсов |
| Regression impact map | Корпоративный ИИ | Веб-интерфейс, затем API | Сначала ручной анализ, затем автоматизация |
| Ревью результатов ИИ | Claude / корпоративный ИИ | Веб-интерфейс | Проверка полноты, логики и рисков |

#### Риски и меры

| Риск | Мера снижения |
|---|---|
| Утечка закрытых данных | Использовать корпоративный ИИ для чувствительной информации; в Claude передавать только моки и обезличенные данные |
| Галлюцинации ИИ | Проверять результат через OpenAPI, JSON Schema, запуск тестов и ручное ревью |
| Зависимость от ИИ | ИИ готовит черновик, человек утверждает сценарий, данные и критерии приёмки |
| Неверные тест-кейсы | Сверять с требованиями, задавать уточняющие вопросы, проводить ручное ревью |
| Хрупкие автотесты | Использовать `data-testid`, role-based selectors, изоляцию данных, запрет произвольных `sleep` |
| Неполная карта сервисов | Хранить манифест зависимостей как код и обновлять при изменениях |

#### Ожидаемый результат

**Экономия времени:** при учёбе 10 часов в неделю ИИ может сократить рутинную часть на 30–40%, то есть примерно на 3–4 часа в неделю.

**Повышение качества:**

- Больше уточняющих вопросов к требованиям.
- Более полные чек-листы и тест-кейсы.
- Быстрая подготовка тестовых данных и моков.
- Более раннее обнаружение проблем в автотестах.
- Лучший анализ логов и причин падений.
- Более системный подход к регрессии по сервисам.

#### 2. Анализ каждого промпта

**Промпт 1 — поиск нетуристических мест.** Роль «местный, который знает тайные уголки» смещает ответ от шаблонных достопримечательностей. Профиль в квадратных скобках (состав, темп, интересы, «не нравится», бюджет, длительность) убирает двусмысленность — модель сразу знает, что фильтровать. Жёсткая спецификация полей на каждое место (зачем идти / лучшее время / стоимость / дорога / длительность) делает формат ответа предсказуемым. Блок «Проверить вручную» — встроенная инструкция не принимать сгенерированные часы и цены за истину, а проверить их перед поездкой.

**Промпт 2 — дешёвые авиабилеты.** Роль «эксперт по поиску дешёвых билетов» задаёт критерии оценки вариантов. Чёткие ограничения: приоритеты (без пересадок, время в пути) и жёсткий лимит по деньгам. Количество вариантов зафиксировано (5) — модель не «усредняет» ответ. Альтернативные аэропорты и даты явно расширяют пространство поиска, а блок «Проверить вручную» со ссылками и визовыми правилами разделяет «модель предлагает» и «человек проверяет».

**Промпт 3 — бюджет поездки.** Двойная роль («финансовый ассистент с двадцатилетним опытом» + «путешественник») сочетает финансовую методологию и практический опыт. Детальные вводные по питанию, транспорту и связи определяют структуру бюджета. Требование дать три оценки (нижняя/средняя/верхняя) плюс резерв 10–15% — диапазон вместо одной цифры, как в нормальном финансовом планировании. «Три совета, где сэкономить без ущерба» — требование практичной, а не описательной пользы.

**Промпт 4 — местный этикет.** Роль «культуролог-практик, общающийся как местный» направляет фокус на практику, а не энциклопедию. Сценарная структура (ресторан, такси, отель, экскурсии) разбивает ответ на ситуации, которые реально встречаются в поездке. Конкретные поля на сценарий (приветствие, одежда, чаевые, 1–2 фразы на местном языке) дают сразу применимый результат. Блок «Проверить вручную» со ссылками на официальные рекомендации турофисов — проверка против авторитетных источников.

**Промпт 5 — индивидуальный маршрут.** Экспертная роль «тревел-гид с знаниями в культуре, архитектуре, искусстве и природе». Явный запрет шаблонности: «не ограничивайся открыточными локациями», «избегай шаблонов и тавтологий» — прямое управление стилем. Персонализация под интересы и требование объяснить, почему каждое место подходит именно пользователю. Фиксированный формат результата (День 1, День 2…) превращает ответ в готовый план. Стилистическая инструкция («пиши тепло, образно, как увлечённый гид») влияет на читаемость.

**Общий паттерн** (подробнее — в разделе 6): во всех пяти промптах есть роль + конкретные вводы в скобках + жёсткая спецификация структуры ответа + количественные рамки + блок ручного контроля.

#### 6. Выводы: какие элементы делают промпт эффективным

- **Роль** («местный», «эксперт по билетам», «финансовый ассистент с 20-летним опытом») задаёт оптику и стиль ответа и сужает пространство возможных ответов — это первый по влиянию элемент во всех пяти промптах.
- **Конкретные вводы в квадратных скобках** — главный механизм. Незаполненный шаблон даёт «пример + вопросы», заполненный — персональное решение. Вся ценность адаптации в тесте была в подстановке данных, а не в переписывании формулировок.
- **Жёсткая спецификация структуры вывода** (какие поля у каждого пункта, какой финальный блок) делает результат предсказуемым и пригодным для использования без ручного переформатирования.
- **Количественные рамки** (10 мест, 5 вариантов, 3 совета, резерв 10–15%) мешают модели «усреднять» ответ и задают нужный объём.
- **Ограничения по профилю** («не нравится: толпы», «бюджет средний») работают как фильтр — в адаптированном ответе действительно нет дорогих и «открыточных» точек.
- **Блок «Проверить вручную»** — самый сильный элемент из всех пяти промптов: он явно разделяет «модель предлагает» и «факты нужно подтвердить», снижая риск принимать сгенерированные часы, цены и ссылки за истину. В обоих ответах блок появился сам, то есть инструкция воспринимается моделью как обязательная часть формата.
- **Против шаблонов** (промпт 5: «избегай шаблонов и тавтологий», «не ограничивайся открыточными локациями») — явное указание на типовую слабость ответа, и модель охотно это соблюдает.

**Практический итог:** готовый чужой промпт — это готовая инструкция, где роль и структура задают ожидаемый результат, вводы — данные, а блок проверки — чек-лист перед поездкой. Самый дешёвый способ улучшить результат чужого промпта — не переписывать формулировки, а корректно заполнить свои данные: в нашем тесте результат вырос со 12 до 24 из 25 баллов при нулевых изменениях текста.
